# geo-llm-visibility-check

[English](README.md) · **Русский**

Десять проверок, которые показывают, видно ли сайт поисковикам **и языковым
моделям**. Один файл на Python, без сторонних библиотек, одна команда.

```
$ python geo_check.py https://example.com

видимость сайта · https://example.com
==========================================================================
 1  доступ ботам моделей и поисковиков прошёл     агентов пропускается 15 из 15, поимённо указано 8
 2  карта сайта                        прошёл     адресов 5, из них с датой правки 5
 3  llms.txt                           прошёл     2697 знаков, строк 49
 4  структурированные данные           НЕ ПРОШЁЛ  структурированных данных нет
 5  мета-теги и язык                   НЕ ПРОШЁЛ  не хватает: описание, canonical, Open Graph
 6  счётчик один на страницу           прошёл     счётчиков по одному: Метрика 12345678
 7  событийные цели                    прошёл     вызовов целей в коде: 1
 8  https и сертификат                 прошёл     действует ещё 40 дн, выдан Let's Encrypt
 9  www и apex согласованы             прошёл     www.example.com сводится к example.com
10  лента материалов                   прошёл     лента найдена по адресу /rss.xml
==========================================================================
Итог: не прошли пункты 4, 5.
```

Ключ `--json` отдаёт тот же результат машиночитаемо — для встраивания куда
угодно.

---

## Для кого

**Маркетинг и SEO.** Про видимость для языковых моделей сейчас говорят все, а
проверяемого чек-листа почти ни у кого нет. Это он и есть, в виде команды.

**Редакции.** Показывает, несут ли страницы материалов структурированные данные
и находится ли лента — две вещи, от которых зависит, будут вас цитировать или
пройдут мимо.

**Магазины и сайты брендов.** Проверки, которые молча стоят денег: дубль
счётчика, раздувающий статистику; отсутствие canonical, расщепляющее страницы;
www и адрес без www, живущие как два разных сайта.

**Тем, у кого сайтов много.** Прогоните в цикле по всем — картина видна сразу.
В нашем собственном прогоне по шести живым сайтам брендов у пяти чего-то не
хватало именно **на главной**, при полностью заполненных подстраницах. Это
сразу сказало, что дело в шаблоне, а не в содержимом.

---

## Почему «и моделям»

Привычные советы по SEO рассчитаны на робота, который обходит страницы и
ранжирует их. Роботы моделей ведут себя иначе, и пускают их иначе:

- Они называют себя **собственными именами**. Сайт, который закрыл звёздочку и
  открыл несколько агентов поимённо, тихо исключит всех, кого забыл назвать. А
  своя группа агента **полностью перекрывает** группу со звёздочкой — так
  написано в стандарте, и это самый частый способ случайно закрыть модель.
- Они награждают **явную структуру**: структурированные данные, объявленный
  canonical, короткое текстовое описание сайта в `llms.txt`.
- Они не станут догадываться о смысле страницы по её вёрстке.

Поэтому проверки здесь — пересечение: всё, что помогает поисковику, плюс те
несколько вещей, от которых зависит, прочтёт ли вас модель вообще.

## Десять проверок

| № | Проверка | Проходит, когда | Зачем |
|---|---|---|---|
| 1 | Доступ ботам | `robots.txt` пропускает 12 названных агентов моделей и 3 поисковых и содержит строку `Sitemap:` | Своя группа агента перекрывает звёздочку. Один забытый — один закрытый робот |
| 2 | Карта сайта | `/sitemap.xml` отвечает и содержит адреса (индекс карт тоже считается) | Без неё робот найдёт только то, до чего дойдёт по ссылкам |
| 3 | `llms.txt` | Файл есть и в нём содержание, а не заглушка | Короткое текстовое описание сайта для моделей. Писать дешево, а такой сводки им больше взять негде |
| 4 | Структурированные данные | Хотя бы один разобравшийся блок JSON-LD осмысленного типа | Здесь вы *заявляете*, что это за страница, вместо надежды, что догадаются. Неразобравшийся блок — провал, а не успех: в бою его молча игнорируют |
| 5 | Мета-теги и язык | `title`, описание, `canonical`, Open Graph, карточка Twitter, `lang` у `<html>` — каждый есть **и не задвоен** | Open Graph — это картинка и подпись при пересылке ссылки. Без него в чат уезжает голый адрес. Два разных `canonical` хуже, чем ни одного: страница выглядит настроенной, а выдача выбирает за вас |
| 6 | Счётчик один на страницу | Ни один идентификатор не запускается дважды, и нет диспетчера тегов с пустым идентификатором контейнера | Дубль ничего не ломает на вид и потому живёт месяцами, считая визиты и отказы вдвое |
| 7 | Событийные цели | В коде страницы есть хотя бы один вызов цели | Без вызовов в коде в кабинете работают только цели по адресу: ни кнопка, ни форма, ни скачивание не считаются. Выводится замечанием, не провалом |
| 8 | HTTPS и сертификат | Цепочка доверия в порядке, осталось больше 14 дней | Две недели — тот срок, к которому автопродление уже пробовало несколько раз и не смогло |
| 9 | www и apex согласованы | Один сводится к другому | Две живые копии сайта делят вес ссылок и раздваивают статистику |
| 10 | Лента материалов | RSS или Atom объявлены в разметке либо отвечают по обычному адресу | Так на вас подписываются агрегаторы и модели. Замечание, не провал |

Пункты 7 и 10 — замечания: на код возврата они не влияют.

## Установка и запуск

Нужен **Python 3.9+** и больше ничего.

```bash
curl -O https://raw.githubusercontent.com/vladimirsave/geo-llm-visibility-check/main/geo_check.py
python geo_check.py https://example.com
```

Ключи:

| Команда | Что делает |
|---|---|
| `python geo_check.py <адрес>` | Таблица, как выше |
| `python geo_check.py <адрес> --json` | Тот же результат в JSON |
| `python geo_check.py --selftest` | 18 проверок разборщиков без сети и без побочных действий |

Код возврата: `0` — все обязательные пункты прошли, `1` — есть провалы. Значит,
годится как заслонка в сборке:

```bash
python geo_check.py https://staging.example.com || exit 1
```

По списку сайтов:

```bash
for host in example.com shop.example.com blog.example.com; do
  python geo_check.py "https://$host" --json >> report.jsonl
done
```

## Что он делает намеренно

**Только читает.** Запрашивает страницу, `robots.txt`, `sitemap.xml`,
`llms.txt` и, возможно, ленту. Ничего не меняет, ничего не отправляет, ничего
не сохраняет.

**Говорит, почему, а не только что.** В каждой строке причина: сколько агентов
пропускается, сколько адресов в карте, какой счётчик продублирован, сколько
дней осталось сертификату. Голое «не прошёл» не говорит, что чинить.

**Разжимает то, что пришло.** Часть серверов за сетями доставки отдаёт gzip,
даже когда его не просили. Пока это не учитывалось, проверка видела двоичный
мусор и сообщала, что на странице нет ни заголовка, ни мета-тегов — то есть
врала. Теперь разжимает по факту, а не по запросу.

**Разбирает `robots.txt` по стандарту.** Идущие подряд строки `User-agent`
образуют одну группу; выигрывает самое длинное совпадение префикса; при равной
длине `Allow` сильнее `Disallow`; своя группа агента заменяет группу со
звёздочкой, а не дополняет её. Каждый из этих пунктов — реальный способ
прочитать файл неверно.

## Чего он не делает

- Не исполняет JavaScript. Разметка, подставляемая на стороне браузера, для
  него невидима — как и для большинства роботов, в чём, собственно, и дело.
- Не сверяет структурированные данные со schema.org. Проверяет, что JSON
  разбирается и типы осмысленны. Для полной сверки есть валидаторы поисковиков.
- Не обходит сайт. Один адрес за прогон, намеренно: вы сами выбираете, какие
  страницы важны, и проходите по ним циклом.
- Не судит содержимое. Ни одна проверка здесь не говорит, хорош ли текст.

## Откуда взялся этот список

Десять проверок — это то, что осталось после нескольких месяцев одинаковой
приёмки живых сайтов брендов. Три из них появились из конкретных потерь:

- **счётчик один на страницу** — дубль прожил недели и вдвое завысил цифры
  трафика, по которым уже принимали решение;
- **событийные цели** — цели в кабинете были, панель выглядела настроенной, а
  в коде страницы не было ни одного вызова, и считались только просмотры;
- **структурированные данные должны разбираться** — блок с лишней запятой
  игнорируется без единого слова. Страница выглядит размеченной и не размечена;
- **задвоение наравне с отсутствием** — проверка сначала смотрела только,
  есть ли тег. На живом сайте нашлись два разных `canonical` и два разных
  описания на одной странице, и проверка их пропустила: тег ведь есть.

И одна оговорка из того же разбора, уже про сам инструмент: номер счётчика
Метрики встречается в коде тремя способами — в адресе скрипта, в вызове `init`
числом и в вызове `init` строкой. Последний ставят плагины готовых систем
управления сайтом. Пока учитывался только первый, проверка сообщала «счётчика
нет» на страницах, где он стоял и работал. Если вы расширяете её под свою
аналитику, считайте все способы, которыми её у вас подключают, — иначе получите
ложную тревогу там, где всё в порядке.
